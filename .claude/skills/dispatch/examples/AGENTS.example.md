# AGENTS.md — repo map for sub-agents

> **This is an anonymized example**, adapted from a real `AGENTS.md` that `/dispatch bootstrap`
> generated for a large WordPress commerce plugin. Names, paths and test names are invented; the
> structure, the proportions and the lessons are real.

Read this before touching anything. It replaces surveying the codebase.

## What this project is

Marketkit — an all-in-one commerce plugin for WordPress. Requires WP 6.4+ and PHP 8.1+.
Text domain `marketkit`. Default PR branch is **`develop`**, not `main`.

Ships in three editions: Lite, Pro (separate `marketkit-pro` plugin, sibling directory) and Cloud
(licensing, third repo `marketkit-cloud`). Themes consume its shortcodes and hooks as a public
contract.

## Layout — what lives where

| Path | Holds | Edit when |
| --- | --- | --- |
| `includes/` | Legacy procedural `MK_*` classes, snake_case, no namespace | Changing behaviour already living here |
| `src/` | New code, `Marketkit\` namespace, PSR-4 | New non-trivial subsystems |
| `assets/css`, `assets/js` | Frontend + admin assets (27 CSS, 23 JS) | Styling and browser behaviour |
| `blocks/src` | Gutenberg block sources (30 blocks) | Block editor work |
| `blocks/build` | **Committed build output** — generated by `npm run blocks:build` | Never by hand; rebuild and commit |
| `templates/` | Frontend PHP templates | Markup changes |
| `tests/` | `Unit`, `Integration`, `Smoke` (168 files), `Browser` | Always, alongside a change |
| `docs/` | Internal docs — never shipped | Design records |
| `vendor/`, `node_modules/` | Dependencies | Never |

**The `includes/` vs `src/` split is the thing to get right.** PHPCS lints `src/` **only**
(`phpcs.xml.dist`). `includes/` is grandfathered out. Follow the file you are already in — do not
half-migrate a legacy class into the namespace as a side effect of an unrelated fix.

## Where things are

- **Bootstrap / entry point:** `marketkit-base.php` — singleton with `load_core()` →
  `init_components()` → `register_hooks()`. No service container. Registers a PSR-4 fallback
  autoloader so new namespaced code works without `composer dump-autoload`.
- **REST routes:** `includes/class-rest-api/class-rest-*.php`, one file per resource.
  **These files are the source of truth for the route list**; `README.md` documents the surface.
- **Shortcodes:** `includes/class-shortcode/` — storefront output is shortcode-driven, not
  blocks-only.
- **Feature gate:** `includes/class-features.php` (`MK_Features`, option `mk_feature_flags`)
- **Schema:** `includes/class-database.php` — the plugin owns its own `wp_mk_*` tables rather
  than reusing WP core tables.
- **Theme contract:** `docs/THEME-CONTRACT.md` — the stable shortcode/hook surface.
- **Database:** MySQL via the site manager; connection in the site config (path below), never
  in this file. Use the read-only user `mk_ro` for checks.

**Breakpoints — use what the file already has; do not invent new ones.** Verified from the
`@media` queries actually present:

| Stylesheet | Breakpoints in use |
| --- | --- |
| `catalog-discovery.css` | 560, 620, 640, 900 |
| `products-shortcode.css` | 560, 760, 900 |
| `archive-product.css` | 768 |
| `single-product.css` | 640, 1023.98, 1024 |
| `cart.css` | 720 |
| `checkout.css` | 480, 768 |
| `account.css` | 640, 900 |

The set is **not** consistent across files — match the file you are editing, not a global rule.
Two that carry meaning: catalog's 900px is where filters become a popup, and `single-product.css`
treats ≤1023.98px as mobile+tablet because its desktop layout starts at `min-width: 1024px`.

> Generating this table by reading the actual `@media` queries — rather than trusting the prose
> in an existing CLAUDE.md — caught a wrong list on the first run. A "do not invent breakpoints"
> rule with an incomplete list is worse than no rule.

## Conventions that will get a change rejected

- `if (!defined('ABSPATH')) { exit; }` at the top of **every** PHP file.
- 4-space indent. No closing `?>` in class files.
- Escape on output — `esc_html_e`, `esc_attr` — always with the `marketkit` text domain.
- Comments explain **why**, in prose, at the density of the surrounding file. This codebase does
  not comment obvious lines.
- Assets are versioned by `filemtime()`, not a version constant. **Editing a CSS file is enough
  to bust the cache — never bump a version for that.**
- A Gutenberg block is a chain: `block.json` attributes → `edit.js` `InspectorControls` →
  `render.php` → the matching shortcode. Change one, check all four.

## Do NOT

- **do NOT** edit `blocks/build/` by hand — it is committed on purpose so a plain `git pull`
  gives a working plugin with no npm step. Edit `blocks/src`, rebuild, commit both.
- **do NOT** edit `vendor/` or `node_modules/`.
- **do NOT** break the edition boundary. Cart, checkout, archive, single product, account,
  order-received, public REST reads and frontend assets **must work with Pro absent and Cloud
  disconnected**. Pro presence is `class_exists('Marketkit_Pro')`. Lite-only UI advertising Pro
  must render as an **inert, disabled** affordance — never load Pro code paths from core.
- **do NOT** load an optional module without its gate — `MK_Features::is_enabled('cart')`.
- **do NOT** change shortcode names, hook names, or documented CSS class names — the theme
  contract is a promise to third parties.

## Local environment

Local dev runs under a WordPress site manager. **Connection details live in the site config —
read them from there, never hardcode them and never print them.**

The bundled binaries need their own lib directory on the library path, and the DB socket path
rotates between restarts, so re-check it before assuming a connection string still works. The
local DB is often down; that is expected, not a bug to chase.

## What not to bother reading

- `vendor/`, `node_modules/` — dependencies.
- `blocks/build/` — generated. Read `blocks/src/` instead.
- `dist/` — packaging output.
- `docs/` — design records and plans, not current-state truth. Read one only when the brief names
  it. `THEME-CONTRACT.md` and the edition-boundary doc are the two that constrain code.
- `tests/Smoke/` in bulk — 168 files. Read only the one covering your surface.
